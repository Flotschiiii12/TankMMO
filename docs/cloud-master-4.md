# Cloud master job 4 (triggered by the user typing just "start4"): the UI/UX overhaul

Goal from the owner: the whole game should look and feel like a polished AAA browser/mobile MMO in the league of Seafight and DarkOrbit. This round is the big overhaul of every menu, the HUD and the screens around the game. You are running unattended and should stay busy for about two hours. The owner will not answer questions: decide sensibly, write the decision down, keep going. Read `CLAUDE.md` first, then `docs/CLOUD_REPORT.md`, `docs/CLOUD_REPORT_2.md`, `docs/CLOUD_REPORT_3.md`, `docs/MOBILE.md`, `docs/screenshots/` (current look) and skim `src/ui/` and `src/index.css` before you design anything. Then execute this file completely.

## Honest framing (read this)
Code alone cannot make a game "AAA": the missing ingredient is hand-made art. You cannot generate or add image files. So: build a strong design system and layouts in CSS/SVG/canvas that already look clean and consistent, and define **art slots** (optional images with CSS fallbacks) so that real art can be dropped in later without code changes. Task 10 produces the ready-to-paste image prompts for the owner. Do not fake art with noisy gradients; clarity, hierarchy, contrast, spacing, rhythm and motion are what make a UI feel premium.

## Setup
1. Start on `claude/unify-client`. Create the working branch `claude/cloud-batch-4`. Separate commits per task, push after every finished task.
2. `npm install --legacy-peer-deps --ignore-scripts`; `npm test`, `npm run lint`, `npm run build` must be green at the start (302 tests). Also run `npm run e2e` and `npm run layout-check` once (set `E2E_CHROMIUM=/opt/pw-browsers/chromium` if needed) and keep both green to the end.

## Rules for every task
- Before committing a task: `npm test`, `npm run lint`, `npm run build` green; after tasks that change layout also `npm run layout-check` and `npm run e2e`. If a task cannot be made green after two honest attempts, drop it, write why, continue. Never leave the branch red.
- Budget about 12 minutes per task; do not stop early; spend leftover time on tests, screenshots and reviewing your own diff.
- Do NOT change game rules, balance numbers, the protocol or the database. This round is presentation and interaction only (small additive server fields are allowed only when a screen truly needs data, with tests and no `PROTOCOL_VERSION` break).
- Never push to `main`, never deploy, never copy art, layouts, names or texts from other games (Seafight, DarkOrbit, Red Galaxy are references for the *level of polish*, not sources). No new image files (art slots must work when the file is missing). Fonts: system stack only, no external requests.
- Mobile first (landscape phones, 844x390 down to 667x375) and keep desktop great. Touch targets >= 44 px, text >= 11 px, respect safe areas. Everything in German and English through `tr()`/`nm()`; informal "du".
- Performance: no per-frame React state updates, no `shadowBlur` on canvas, CSS animations only on `transform`/`opacity`, honour "Reduced effects"/"Performance mode"/`prefers-reduced-motion`. Screen shake stays OFF (the owner removed it on purpose).
- Keep every existing feature reachable; nothing may disappear. Keep the code organised: small components, shared kit, no 1500-line files (split `GameShell.tsx` while you are there if it helps).

## Tasks, in this order

### 1. Design system and UI kit
Create `src/ui/kit/`: design tokens (colour roles, spacing scale, type scale, radii, elevation, motion durations/easings, z-index layers) as CSS variables in one place, three faction themes (coastal blue, highland green/orange, steppe gold/red) that switch accent colours, light-on-dark high-contrast base. Components: Panel/Card with header and optional art-slot border, Button (primary/secondary/danger/ghost/icon, loading, disabled, pressed states), Tabs, SegmentedControl, Tooltip (touch-friendly long-press), Badge/Pip/Counter, ProgressBar and ring (hull/armor/xp), CurrencyChip, StatRow with delta arrows, ItemCard (rarity frame, icon, upgrade level, affixes in colour), List/Grid with virtual scrolling for long lists, Toast, Modal/Sheet, EmptyState, Skeleton loaders. Art slots: components read optional `public/assets/ui/*.png` (listed in the manifest) and fall back to CSS. Build a dev-only gallery route `/ui-gallery` that shows every component in every state, in both languages and all three faction themes, and a Playwright script that screenshots it. Write `docs/UI_KIT.md` (usage, tokens, rules). Tests for the pure logic (rarity colour mapping, delta formatting, tooltip positioning).

### 2. Window manager, main navigation and top bar
Replace the ad-hoc modals with one window system: stacking and focus, Escape/back closes the top window, consistent header with title/close, desktop windows can be dragged and remember position, phones get full-height sheets, focus trap, keyboard shortcuts shown in a help overlay (I inventory, Q quests, M map, C clan/social, G garage...). A persistent main menu (icon rail on the right/left, mirrored for left-handed mode) with notification pips (new items, quest ready to turn in, unread mail, clan invite, event running). A top player card: avatar/rank badge, name, level with XP ring, faction crest, currencies as CurrencyChips with the painted icons, and a compact settings/sound menu. Use the existing icons and badges. Update `layout-check` so it understands the new structure and keep it at 0 violations.

### 3. In-game HUD redesign
Redo the in-game HUD around clear zones: status cluster (hull/armor/XP rings, buffs), minimap top-right with zone name and coordinates and a toggle for bigger map, target frame top-centre (name, level, hull/armor, statuses, ammo effectiveness), a hotbar bottom-centre (abilities with cooldown sweep and key hints, ammo selector with icons and counts, fire/lock buttons for touch), chat dock bottom-left that collapses to a one-line ticker, quest tracker, party frames, event chips, a notification centre with grouped toasts (loot, XP, quest, system) and a short history. Phone layout must keep the joystick and fire cluster free (the layout checker proves it). Add a "HUD scale" and "HUD opacity" setting and a "minimal HUD" mode. Add an interactive HUD layout test (Playwright) for 844x390.

### 4. Hangar: garage and loadout
Rebuild the garage as a hangar: a large preview of the selected vehicle (hull and turret sprites, drones orbiting, skin glow) with slots arranged around it (main weapons, secondary, armor, engine, modules, drones), drag and drop (and tap-to-assign on phones) between inventory and slots, stat panel with live preview and green/red deltas when hovering an item, power rating bar, a vehicle carousel (50 vehicles by class and tier, locked ones show the level/scrap/ore requirement and what they unlock), skin picker, "equip best" and "unequip all" with confirmation, loadout presets (save/load 3 presets, client-side validated, server-authoritative equip). ItemCards and tooltips from the kit everywhere.

### 5. Inventory, workshop, market, mail
Redesign inventory (grid with filters by slot/rarity/tier, sort, search, bag capacity bar, quick actions, compare with equipped, bulk dismantle with a safety review list), workshop (upgrade with success chance, costs and what you lose on failure shown clearly; crafting browser with a "can craft now" filter and missing-materials highlight; reroll and fusion flows with previews), the auction house (search/filters, sell wizard with suggested price from the NPC value band and recent sales, my listings with time left, buy confirmation), direct trade (two-column offer view with confirm states) and mail (inbox with attachments, claim all). All through the kit, with empty states and skeleton loading.

### 6. World map, quests, journal, codex, achievements, talents, season pass
Redo these screens consistently: world map (30 zones as a styled map with fog for unvisited, faction territory colours, level ranges, safe/PvP markers, gates, event and war markers, fast-travel with cost, zone detail card), quest log (tracked quest pin, categories, rewards preview, story journal with the dialogue replay), codex and achievements (grids with progress, rarity, filters), talent tree (a real node-and-line graph for the 3 branches with rank pips, prerequisites, respec flow and point counter), season pass (50-tier track with free rewards, claim states, time left). Keyboard and touch navigable.

### 7. Social suite
Friends list with presence and quick actions, party finder and party panel, clan hub (emblem, roster with roles, storage, alliances, research, log), chat redesign (channel tabs with unread pips, filters, mentions, emotes, item links, slow-mode and mute info, report/block in a context menu), a public player profile/inspect card (rank, honor, clan, vehicle preview, achievements; no private data), leaderboards (level, honor, arena, clans) with "my position" row and season info. Reuse server ops that exist; add small read-only fields only where needed and tested.

### 8. Title, login, loading, settings
Make the first minutes feel premium: a title screen with logo treatment, news/patch-notes panel (data-driven from a small JSON the server serves, with an admin editor field), server status, language switch, guest vs recovery login flow polished, faction selection as a proper presentation (crest, colours, start region, short story blurb, what changes and what does not), loading screens with tips (write 60 tips DE/EN) and a progress bar, smooth transitions between maps (fade, zone-name banner with level range), and a rebuilt settings window with tabs (Graphics, Audio, Controls with keybinding remap, Interface, Accessibility, Account with data export/delete, About with version and legal links to `docs/legal`).

### 9. Audio and motion polish
No audio files exist, so build it with Web Audio synthesis: a small sound engine with buses (master/music/effects/interface) and a mixer in the settings, UI sounds (hover, click, open/close, error, success, reward), weapon sounds per family, hit/explosion/impact by size, engine hum by class and speed, ambient per biome, and a generative adaptive music layer (calm exploration vs combat intensity) that is gentle and loops without fatigue (keep it optional, default low). Add a motion system: consistent enter/exit transitions for windows and toasts, number count-up for rewards, a loot/reward reveal animation, a level-up celebration, rank-up and quest-complete banners; all respect reduced motion. Tests for the pure parts (bus gain maths, music state machine transitions).

### 10. Visual QA harness and the art brief for the owner
Build `scripts/ui-shots.ts` (`npm run ui-shots`): Playwright screenshots of every screen and window in DE and EN, at 844x390, 667x375 and 1280x720, in all three faction themes, saved under `docs/screenshots/ui/`, plus a simple pixel-diff mode against the previous run to catch accidental regressions (opt-in CI job). Add an accessibility pass (contrast ratios of the tokens computed in a unit test, keyboard navigation through every window, focus rings, aria labels) and a performance budget check (bundle size limit, first render time in e2e). Then write `docs/bildprompts-ui.md`: the complete list of art the owner should generate for the premium look, each with a ready-to-paste English prompt in the project's established painted style (see `docs/bildprompts-phase3.md` for the format and the style block), the exact target filename under `public/assets/ui/`, size, and which kit component slot loads it: panel and window frames (with 9-slice guidance), button states, tab styles, ability/hotbar frames, rarity frames for item cards (5), hangar background, title/login background art per faction, loading screen illustrations (6), map frame and parchment, badge/ribbon decorations, logo lockup. Write it so the owner can generate the sheets and the existing cutting scripts approach can slice them.
